# Lateralis synthetic dataset

300 synthetic company networks, each with 7 days of normal login activity and one injected
multi-step attack (3 to 6 hops) from a workstation to a critical asset. Generated by
`src/attackpath/data/synthetic.py` (seed 42) and exported with `scripts/export_dataset.py`.

Timestamps follow the app's calendar mapping: day 1 of the synthetic week is the Monday of
last week, so dates shift when you re-export in a later week. `time_seconds` never changes.

## Files

| File | Rows | What it is |
|---|---|---|
| `networks.csv` | 300 | One row per network: size, train/val/test split, attack summary |
| `nodes.csv` | 32,552 | Every machine and user, with role and critical-asset flag |
| `attack_hops.csv` | 1,337 | Every attack hop: when, which account, from which machine to which |
| `events_NET-062.csv` | 5,709 | All login events of NET-062, the demo network in the console |
| `events_all.csv.gz` | 1,398,935 | All login events of all networks (12.5 MB compressed, not in Git) |

## Columns

**networks.csv**: `graph_id`, `network` (NET-xxx), `split` (train 210 / val 45 / test 45),
`workstations`, `servers`, `critical_assets`, `users`, `login_events`, `attack_events`,
`attack_hops`, `entry_machine`, `target_machine`, `target_role` (domain_controller or database),
`attack_path` (machines in order), `attack_start`, `attack_end`.

**nodes.csv**: `graph_id`, `network`, `node` (C… machine or U… user), `kind` (computer / user),
`role` (workstation, file_server, mail_server, app_server, web_server, print_server,
domain_controller, database for machines; regular, admin, service for users), `is_critical`.

**attack_hops.csv**: `graph_id`, `network`, `hop` (1 = first move), `timestamp`, `time_seconds`,
`user` (the stolen account used), `src`, `dst`.

**events_*.csv**: `graph_id`, `timestamp`, `time_seconds` (seconds from the start of the week),
`user`, `src` (machine logged in from), `dst` (machine logged in to; equal to `src` for a local logon),
`attack_step` (0 = normal, 1..6 = attack hop), `is_attack`.

## How the data is made

- **Network:** 25–70 workstations (one user each, about 8% of them admins), 4–10 servers, one domain
  controller and 1–2 databases. Service accounts connect app servers to databases around the clock.
- **Normal behaviour:** logins cluster around 10:00 and 15:00, drop at weekends, and include realistic
  noise: hot-desking (6% of user logins from another desk), admins working from servers (30%), and
  rare logins to unusual servers (1%).
- **Attack:** starts after two days of normal history at a random workstation. At each machine the
  attacker steals the credentials of accounts that log in there and moves on, preferring machines
  where admins log in and servers (credential dumping, MITRE ATT&CK T1003), until it reaches a
  domain controller or database. Retries on the same hop appear as extra attack events.
- **Balance:** attack events are 0.16% of all events.

Regenerate everything with:

```bash
.venv/bin/python -m attackpath.data.synthetic --n-graphs 300
.venv/bin/python -m attackpath.graph.builder
.venv/bin/python scripts/export_dataset.py
```
